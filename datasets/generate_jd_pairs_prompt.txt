YOUR TASK
================================================================================

STEP 1 — Generate exactly 5 Job Descriptions

Rules for each JD:
  - Each JD targets ONE specific resume as its PRIMARY match (the resume with the
    same numeric suffix, e.g., resume_456 → jd_456).
  - Write in realistic HR language. Do NOT copy exact phrases from the resume text.
  - Requirements must be slightly broader than the resume:
      * Use experience ranges (e.g., "3–6 years", not "exactly 5 years").
      * Add 1–2 adjacent/preferred skills the target resume does not have.
      * Include 2–3 transferable soft skills (e.g., "strong analytical thinking",
        "comfortable working in agile teams") so off-diagonal pairs always score
        at least weak_match (40–59) — never below 40.
  - Domain and level must match the target resume's field and seniority.
  - Design each JD so the diagonal pair scores **90–95** (targeting excellent_match).
    Craft requirements to align tightly with the target resume's core stack so the
    weighted score naturally lands ≥ 90. Only drop below 90 if the resume has a clear
    gap that cannot be bridged by the JD design.

STEP 2 — Generate exactly 25 Pairs (5 JDs × 5 Resumes)

Rules:
  - Evaluate EVERY combination of the 5 JDs against all 5 resumes.
  - Iteration order: outer = JDs (sorted by jd_id), inner = resumes (sorted by
    resume_id). Example for IDs 456–460:
      pair_2276 = jd_456 × resume_456   ← diagonal (target: high)
      pair_2277 = jd_456 × resume_457
      pair_2278 = jd_456 × resume_458
      pair_2279 = jd_456 × resume_459
      pair_2280 = jd_456 × resume_460
      pair_2281 = jd_457 × resume_456
      pair_2282 = jd_457 × resume_457   ← diagonal (target: high)
      ... and so on until pair_2300 = jd_460 × resume_460
  - Score each pair honestly based on actual resume content vs JD requirements.
  - Aim for score distribution:
      * Diagonal pairs (JD_i ↔ target resume_i): **90–95** (excellent_match preferred)
      * Off-diagonal pairs: vary realistically between 50–79 (minimum 40).
        Prefer moderate_match (60–74) and strong_match (75–79) for resumes with
        overlapping domains; use weak_match (50–59) only for clearly mismatched domains.
      * Do NOT assign the same low score to all off-diagonal pairs.
      * At least 2 off-diagonal pairs per JD should reach strong_match (75–89) to
        ensure the model learns fine-grained discrimination, not just excellent vs. weak.

================================================================================
SCORING RUBRIC  (rubric_v0.2)
================================================================================

Overall score formula — WEIGHTED average (NOT a simple mean):

  overall_score =
    SKILLS_MATCH             × 0.35
    + EXPERIENCE_RELEVANCE   × 0.30
    + PROJECT_RELEVANCE      × 0.15
    + EDUCATION_CERTIFICATION× 0.10
    + KEYWORD_DOMAIN_ALIGNMENT × 0.10

Round the result to the nearest integer.

Criterion guidance:

  SKILLS_MATCH (35%)
    90–100  Covers almost all required skills with clear evidence
    75–89   Covers most required skills, minor gaps only
    60–74   Covers some required skills, misses important items
    40–59   Broad overlap but missing the core stack
    0–39    Little or no overlap with required skills
    Note: do not reward keyword mentions without project/work evidence.

  EXPERIENCE_RELEVANCE (30%)
    90–100  Experience clearly exceeds role expectations
    75–89   Experience fits the role well
    60–74   Related but shallow or incomplete
    40–59   Limited practical evidence
    0–39    No relevant experience or projects
    Note: for intern JDs, academic/personal projects count as evidence.

  PROJECT_RELEVANCE (15%)
    Evaluate whether resume projects demonstrate the same stack, problem type,
    or responsibilities as the JD. Examples:
    - backend API JD + FastAPI/PostgreSQL project = high
    - DevOps JD + only frontend UI projects = low
    - AI data JD + dataset/evaluation project = high

  EDUCATION_CERTIFICATION (10%)
    90–100  Directly matches required degree and field
    75–89   Related degree or strong equivalent background
    60–74   Partially related education
    40–59   Education is unclear or weakly related
    0–39    Does not meet explicit education requirement
    Note: if JD does not mention education, use a neutral score (~70).

  KEYWORD_DOMAIN_ALIGNMENT (10%)
    Evaluate overlap in responsibilities, domain keywords, and business/
    technical context between the JD and the resume.

Label class mapping (from overall_score):

  90–100 → "excellent_match"
  75–89  → "strong_match"
  60–74  → "moderate_match"
  40–59  → "weak_match"

  DO NOT use "poor_match". Scores below 40 are not allowed.
  If an off-diagonal pair would naturally score below 40, redesign the JD
  to include broader soft skills so the minimum achievable score is 40.
