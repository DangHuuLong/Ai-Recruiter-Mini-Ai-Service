================================================================================
SCORING RUBRIC  (rubric_v0.2)
================================================================================

Overall score formula — WEIGHTED average (NOT a simple mean):

  overall_score =
    SKILLS_MATCH             × 0.35
    + EXPERIENCE_RELEVANCE   × 0.30
    + PROJECT_RELEVANCE      × 0.15
    + EDUCATION_CERTIFICATION× 0.10
    + KEYWORD_DOMAIN_ALIGNMENT × 0.10

Round the result to the nearest integer.

Criterion guidance:

  SKILLS_MATCH (35%)
    90–100  Covers almost all required skills with clear evidence
    75–89   Covers most required skills, minor gaps only
    60–74   Covers some required skills, misses important items
    40–59   Broad overlap but missing the core stack
    0–39    Little or no overlap with required skills
    Note: do not reward keyword mentions without project/work evidence.

  EXPERIENCE_RELEVANCE (30%)
    90–100  Experience clearly exceeds role expectations
    75–89   Experience fits the role well
    60–74   Related but shallow or incomplete
    40–59   Limited practical evidence
    0–39    No relevant experience or projects
    Note: for intern JDs, academic/personal projects count as evidence.

  PROJECT_RELEVANCE (15%)
    Evaluate whether resume projects demonstrate the same stack, problem type,
    or responsibilities as the JD. Examples:
    - backend API JD + FastAPI/PostgreSQL project = high
    - DevOps JD + only frontend UI projects = low
    - AI data JD + dataset/evaluation project = high

  EDUCATION_CERTIFICATION (10%)
    90–100  Directly matches required degree and field
    75–89   Related degree or strong equivalent background
    60–74   Partially related education
    40–59   Education is unclear or weakly related
    0–39    Does not meet explicit education requirement
    Note: if JD does not mention education, use a neutral score (~70).

  KEYWORD_DOMAIN_ALIGNMENT (10%)
    Evaluate overlap in responsibilities, domain keywords, and business/
    technical context between the JD and the resume.

Label class mapping (from overall_score):

  90–100 → "excellent_match"
  75–89  → "strong_match"
  60–74  → "moderate_match"
  40–59  → "weak_match"
  0–39   → "poor_match"

  All five labels are valid. Use poor_match only for genuine mismatches, not as a
  default floor — scores must reflect actual resume-JD alignment.
